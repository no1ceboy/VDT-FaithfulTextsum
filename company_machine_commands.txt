VDT-FaithfulTextsum company run

From the repo root, use the IT-approved environment. Do not pip-install or
download models from Hugging Face. Merge the current code ZIP over the source;
preserve `models/`.

Extract MiniCheck into the existing cache (the ZIP has files at its root):

  python -m zipfile -e VDT-FaithfulTextsum-MiniCheck-Flan-T5-Large.zip models/hf-cache

The evaluator searches recursively below `models/hf-cache`, so these are also
valid: `models/hf-cache/MiniCheck-Flan-T5-Large/` or an uploaded wrapper such
as `models/hf-cache/uploaded/MiniCheck-Flan-T5-Large/`. The selected model
folder must directly contain `config.json`, model weights, and `spiece.model`
or `tokenizer.json`. Do not point at a `blobs/` directory.

Clean the loaded batch_3 dataset before training or generation. This writes a
new file, leaves the original unchanged, and writes the report/audit under
`results/`. The legacy fields are `input` and `output`:

  python3 -m src.data.clean_dataset \
    --input data/batch_3.jsonl \
    --output data/batch_3_cleaned.jsonl \
    --source_col input \
    --reference_col output \
    --replacement_policy drop \
    --drop_stale_token_lengths \
    --report results/batch_3_cleaning.json \
    --audit_log results/batch_3_cleaning.audit.jsonl

The cleaner replaces links with `[URL]`, removes decorative icons and
separator lines, and drops empty/corrupted source rows. Do not add
`--overwrite` on the first run; add it only when intentionally rerunning the
same output path.

Use `data/batch_3_cleaned.jsonl` below as the input for later preparation:

  python3 scripts/prepare_grpo_data.py \
    --input data/batch_3_cleaned.jsonl \
    --source_col input \
    --reference_col output \
    --output_dir results/batch_3_grpo_splits \
    --validation_fraction 0.1 \
    --test_fraction 0.1 \
    --seed 42

10-record evaluation smoke test (auto-detects canonical `text`/`summary` or legacy fields):

  python -m src.evaluate.run_eval \
    --data /data/vdt/summaries.jsonl \
    --offline \
    --nltk_data_dir models/nltk_data \

After it succeeds, rerun without `--limit 10`; change output to
`results/baseline.jsonl`.

Claim/evidence audit of the cleaned batch_3 reference (low-memory; start with 20 rows):

    --offline \
    --output results/batch_3_human_claim_audit.jsonl

Manual review of 20 human-summary documents. First create the lightweight
claim/evidence file; this does not require mFACT:

  python3 -m src.evaluate.fact_audit \
    --data data/batch_3_cleaned.jsonl \
    --source_col input \
    --summary_col output \
    --no_mfact \
    --split_clauses \
    --top_k 3 \
    --output results/batch_3_human_claim_audit_retrieval.jsonl

Then create the offline browser form and editable JSONL template. This selects
10 automatically flagged and 10 unflagged documents with seed 42:

  python3 -m src.evaluate.manual_review \
    --data data/batch_3_cleaned.jsonl \
    --audit results/batch_3_human_claim_audit_retrieval.jsonl \
    --jsonl results/batch_3_manual_review_20.jsonl \
    --html results/batch_3_manual_review_20.html \
    --documents 20 \
    --flagged_fraction 0.5 \
    --seed 42 \
    --source_col input \
    --summary_col output

Open results/batch_3_manual_review_20.html in a browser, label each item as
supported, contradicted, not_supported, unclear, or not_a_claim. Use
not_a_claim for headings, labels, and fragments that do not assert a fact; add
notes if needed, then click Download completed JSONL. Automatic flags are
triage hints, not labels.

Two-stage LLM claim audit. First locate exact factual spans. Candidate spans
are taken from the original summary; the model only answers is_claim, and the
accepted rows retain the original text plus character offsets:

  python3 -m src.evaluate.claim_extractor --backend gemini --model gemini-3.5-flash-lite --input data/batch_3_cleaned.jsonl --source_col input --summary_col output --output results/batch_3_claims.gemini.jsonl --non_claim_output results/batch_3_non_claims.gemini.jsonl --error_output results/batch_3_claim_extraction_errors.jsonl --limit 1 --sleep_seconds 0.2

Remove --limit 1 for all documents. Then verify only the recovered claims:

Claim extraction preserves full sentences by default. Do not enable clause
splitting for heading-style text such as `Tuoi Than: gap nhieu rac roi trong
cong viec`; `--split_clauses` is available only for a deliberate ablation.

  python3 -m src.evaluate.llm_claim_judge --backend gemini --model gemini-3.5-flash-lite --input results/batch_3_claims.gemini.jsonl --output results/batch_3_claim_verdicts.gemini.jsonl --overwrite

For a local model, replace the Gemini backend/model in both commands with a
local instruction model. For Llama 3.2 3B, use
--backend local --model models/Llama-3.2-3B-Instruct --device cuda
--dtype bfloat16 --max_new_tokens 128. The local backend does not download by
default. It accepts common Llama response variants and makes at most one
repair attempt when the first response is malformed. Remove --limit 1 after
the smoke test. Error rows preserve the raw model response, and accepted rows
record claimness_raw_attempts and claimness_repair_attempted.

Optional LLM second-rater pass over the manual-review packet. This does not overwrite human_label. The
Gemini backend sends source text to Google, so use it only if company policy
approves that transfer. Set GEMINI_API_KEY in the environment outside this
file; never paste the key into a command or JSONL:

  python3 -m src.evaluate.llm_claim_judge --backend gemini --model gemini-3.5-flash-lite --input results/batch_3_manual_review_20.jsonl --output results/batch_3_manual_review_20.gemini.jsonl --limit 1 --overwrite

The one-row command is a smoke test. Remove --limit 1 for all claims. If a
run stops, repeat with --resume instead of --overwrite:

  python3 -m src.evaluate.llm_claim_judge --backend gemini --model gemini-3.5-flash-lite --input results/batch_3_manual_review_20.jsonl --output results/batch_3_manual_review_20.gemini.jsonl --resume

The verification judge requires label, reason, evidence_quote, and confidence
in one structured response. Local malformed responses are retried once; every
successful or failed row preserves the raw response attempts for diagnosis.

Offline local-LLM second rater. The checkpoint must already be complete under
models/; this command does not download anything by default:

  python3 -m src.evaluate.llm_claim_judge --backend local --model models/Qwen2.5-3B-Instruct --input results/batch_3_manual_review_20.jsonl --output results/batch_3_manual_review_20.local.jsonl --device auto --max_input_tokens 8192 --overwrite

Recover actual factual claims after either human or LLM labeling. A claim is
a minimal unit that asserts an event, state, relation, quantity, or other
proposition with a truth value checkable against the source. Headings and
topic labels remain available but are excluded from the claim file:

  python3 -m src.evaluate.claim_recovery --input results/batch_3_manual_review_20.gemini.jsonl --label_col llm_label --output results/batch_3_claims.gemini.jsonl --non_claim_output results/batch_3_non_claims.gemini.jsonl --unresolved_output results/batch_3_unresolved.gemini.jsonl

For manual labels, replace --label_col llm_label with --label_col human_label.
not_supported is still an actual claim; only not_a_claim is excluded.

`train.jsonl` for updates, `validation.jsonl` for model selection, and keep
`test.jsonl` untouched until the final comparison.

All experiments below use the same split, seed, one-epoch budget, explicit
validation file, TensorBoard logging, and unique output directories. Run them
separately; do not reuse an output directory. They require IT-provisioned
TRL 1.9.2, PEFT, TensorBoard, and (for the first two) vLLM.

After each run, generate validation summaries from the same validation rows,
then score them with the same metrics and decoding settings. For LoRA use
`final_adapter` plus `--base_model`; for FFT use `final_model` alone. Keep
each generated column and scored file under a unique name. Create a report
with `scripts/make_report.py --run_dir outputs/<run-name>` so the report
includes the run manifest and training history. Keep `test.jsonl` untouched
until the final frozen comparison. See `GRPO_EXPERIMENT.md` for the research
limitations and reporting checklist.
